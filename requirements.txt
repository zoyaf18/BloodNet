# Runtime dependencies for the bloodnet-api container (see Dockerfile).
#
# This mirrors pyproject.toml's base `dependencies` plus the `api`, `ml`,
# and `sim` optional-dependency groups:
#   - api:  main.py / services/match-svc, services/swarm-svc (FastAPI)
#   - ml:   services/match-svc/scoring.py (loads ml/donor_success/model.joblib)
#   - sim:  services/swarm-svc/poisson_binomial.py (numpy). simpy itself is
#           only used by sim/engine.py, which the API container doesn't
#           import, but it's cheap to keep the group intact and in sync
#           with pyproject.toml rather than hand-splitting it.
#
# pyproject.toml is still the source of truth for these version floors.
# If you change one there, update it here too — a plain `pip install
# .[api,ml,sim]` isn't used for the image build because pyproject.toml's
# [tool.setuptools] packages list only picks up .py files sitting directly
# inside each named top-level directory. contracts/ and sim/ qualify;
# services/match-svc/*.py and ml/donor_success/*.py sit one level deeper
# and are silently left out of a non-editable wheel (confirmed by actually
# building one — no error, the files just aren't there). `pip install -e .`
# is unaffected (that's what pytest uses) and application code never
# imports through the installed `bloodnet` package anyway — every service
# is loaded by file path (see main.py, tests_e2e/test_phase1_e2e.py) — so
# this is a non-blocking, pre-existing packaging quirk, not something this
# container works around by necessity. Copying source directly (see
# Dockerfile) sidesteps it either way.
